# Security Policy

## Reporting a vulnerability
Do not disclose exploitable vulnerabilities in public issues or discussions. Use GitHub's private vulnerability reporting / Security Advisories feature for this repository. If that channel is unavailable, contact the repository owner privately through a verified GitHub contact route.

## Include
- Affected commit, tag, or version.
- Impact and attack preconditions.
- Minimal reproduction or proof of concept.
- Suggested mitigation, if known.

Do not include real credentials, private user data, or destructive payloads.

## Response
The project lead will acknowledge reports as soon as reasonably possible, validate impact, coordinate a fix, and agree on disclosure timing with the reporter. No fixed SLA is promised while the project is volunteer-maintained.

## Scope
Security reports should focus on vulnerabilities in this repository and its supported build, runtime, and release processes. Third-party dependency vulnerabilities should include the affected dependency and reachable impact.
