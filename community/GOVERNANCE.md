# GoTorch Community Governance

## Purpose
This document defines how the project is maintained, how decisions are made, and how contributors can earn responsibility. Governance should evolve with the contributor base; it must not imply that a committee or team exists before it is formed.

## Roles
- **Project lead / owner:** currently the repository owner, responsible for project direction, repository administration, releases, and final resolution when consensus cannot be reached.
- **Maintainer:** a trusted contributor explicitly granted write or review authority. Maintainers review changes, protect project quality, and help triage issues.
- **Contributor:** anyone submitting issues, documentation, tests, code, reviews, or design proposals.
- **Community participant:** anyone participating in discussions and helping users.

## Decision process
1. Small, reversible changes may be proposed through issues or pull requests.
2. Cross-package, public API, numerical contract, security, or compatibility changes require an architecture proposal and an ADR.
3. Discussion should focus on evidence, trade-offs, maintainability, and user impact.
4. The project lead makes the final decision after considering maintainer and community feedback.
5. Record accepted significant decisions in docs/adr/ with status, context, decision, alternatives, and consequences.

## Maintainer appointment
Maintainers are appointed by the project lead based on sustained, constructive contributions, review quality, technical judgment, and community conduct. Access is granted with least privilege and can be reviewed or revoked.

## Conflict resolution
Start with respectful direct discussion; escalate to a maintainer or project lead if unresolved. The Code of Conduct applies to all project spaces. Security reports must use the private reporting path.

## Transparency
Decisions affecting public APIs, supported platforms, release policy, and project direction should be documented publicly unless disclosure creates a security or privacy risk.

## Amendments
Governance changes are proposed as pull requests and become effective after approval by the project lead.
