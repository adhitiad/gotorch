# Documentation Rules

- Keep README concise and link to authoritative detailed documents.
- State project status and platform support accurately.
- Distinguish implemented, experimental, planned, and unsupported capabilities.
- Every public API example must compile or be clearly marked as pseudocode.
- Include prerequisites, commands, expected output, and known limitations in tutorials.
- Architecture changes require an ADR when they affect public contracts or cross-package behavior.
- Avoid unsupported claims about speed, compatibility, completeness, or ecosystem maturity.
- Prefer plain language and stable relative links within the repository.
