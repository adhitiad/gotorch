# Git and Release Rules

- Do not run `git commit` or `git push` until the repository owner explicitly instructs it in the current conversation.
- Commit and push only to `main`. Do not use feature branches, `adhitiad_gpt`, or any other branch.
- Use Conventional Commits with Indonesian descriptions and keep commits atomic.
- Never force-push or rewrite public history.
- Never commit credentials, tokens, private keys, local environment files, or user data.
- Include verification evidence in the completion report.
- Do not merge with failing required checks or unresolved blocking review comments.
- Do not tag or publish a release until the release readiness checklist is complete.
- Keep roadmap and release claims evidence-based; planned work is not implemented work.
